## 本次修的是什么

1. **网页 flag-off 门禁从未真正通过。** `apps/web/e2e/a2ui-email.spec.ts` 的
   「flag is off」用例把 fixture 当成"不提供卡片"的部署，却没把 `a2uiEnabled={false}`
   传给时间线，于是它照样画卡片，断言的计数 0 必然失败。只断言"0 张卡片"本身也是假通过：
   整段会话渲染失败时同样为 0。现在用例要求出现 "interactive cards are off on this
   server" 这句提示、没有 Send，并留存截图。
2. **手机端空白卡片。** 一张取不到文档的卡片此前只画标题、正文空白，正是审计看到的
   空白框。现在明确写"无法显示此卡片"，带存证 ref 且确实有取数函数时给出"重新尝试"，
   按下会真的重新拉取；没有可取数路径时不画这个按钮，避免画一个改变不了结果的控件。
3. **手机端卡片被当作文本。** 行组件调用 `messageHasInlineControls` 时没把服务端的
   `a2uiEnabled` 传进去，于是一张已渲染的卡片仍被当成纯文本，双击会去点赞消息而不是
   聚焦卡片里的输入框。

服务端授权、持久化、事件与流式路径本次未改动；`/me` 的 `a2uiEnabled` 三态服务端优先
逻辑在更早的提交（`4af9dcc52`）已就位。

## 现场排查提示（`/app/<id>`）

`https://app.matebot.dev/app/cmw3ccoycmat5g4eo037s2ta0` 最后一段是 **bot id**，不是
thread id（`apps/web/src/App.tsx` 的 `/app/:botId` 路由）。之前把它当 thread id 查当然
查不到，那**不能**说明卡片从未生成。正确入口：

```bash
bash docs/architecture/diagnose-a2ui-card-readonly.sh cmw3ccoycmat5g4eo037s2ta0 "$DATABASE_URL"
```

脚本只读、只输出 id/枚举/时间/计数，先从 bot 解析出 thread，再查该 thread 的卡片块、
interaction、surface 文档长度、相关事件与 run。注意：Event 行只能证明服务端记录了发送
意图，不能证明 SSE 帧到达浏览器；渲染与否只有浏览器能回答。
